# V1.1 to V1.2 audit

Status: TESTED / CPU_VERIFIED. V1 and V1.1 artifacts were preserved. `artifacts/v11/mujoco_reach/act/failed_seed_2014.json` exactly matches the stored evaluation trace in actions, states, rewards and checkpoint hash; the MP4 decodes. The V1.1 checkpoint includes model, optimizer and CPU RNG states. No scheduler was configured, so there is no scheduler state to restore. CUDA RNG restoration is not implemented.

The ACT implementation predicts action chunks with a CVAE posterior, positional embeddings and reconstruction/KL losses. It executes the first action of each predicted chunk, replanning every control step; temporal aggregation is not implemented. V1.2a exposed a concrete train/inference mismatch: most training reconstructions used a sampled posterior latent, while inference used zero latent. On 100 training states, mean absolute first-action targets were about `[0.262,0.276,0.263,0]`, but inference predicted about `[0.011,0.008,0.007,0.005]`. V1.2b trained half of samples with zero latent and standardized states from training data only. The V1.2a failure result remains intact.

The Diffusion model uses a cosine forward noise schedule, noise-prediction loss and posterior-variance reverse steps. Its 4-step sequence is sampled every control step and only the first action executes. It clips final normalized actions to `[-1,1]`, matching FetchPush's action space. 500 updates in V1.2a yielded high validation error; 2000 updates in V1.2b improved it, and 30,000 updates were tested in a separate approximately equal CPU-time control. It remains a small MLP denoiser, not a canonical visual Diffusion Policy U-Net.

IQL still follows expectile value, double-Q Bellman update, target interpolation and advantage-weighted action regression. Success termination and timeout are separate. No V1.2 IQL run on FetchPush has been completed, so earlier point-reach IQL numbers cannot be compared with FetchPush policies.

CEM bounds actions and performs actual elite updates. V1.1's point-reach terminal cost was task-specific; V1.2 added an explicit terminal-cost function for FetchPush. The FetchPush physics oracle snapshots and restores MuJoCo joint, actuator, mocap, warmstart, goal and elapsed-step state. A test checks that candidate predictions leave the actual environment unchanged. Its candidate rollouts use only the current physical state, not observed future test states.

Dataset split audit: the old general `split_episodes` function overlapped train/test for one episode; it now rejects fewer than three unique IDs. FetchPush uses distinct training, validation, exploratory, confirmatory and OOD seed ranges. Within each training seed, ACT and Diffusion receive the exact same saved demonstrations and action normalization. Their architectures and wall-clock costs differ, so equal-update comparisons are not equal-compute comparisons.
