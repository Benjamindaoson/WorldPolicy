# FetchPush robot world model and planning

Status: **CPU_VERIFIED**, exploratory V1.2 model and planners; no new confirmatory planning gain in V1.3. The robot ensemble is three MLPs trained on 3,107 *actual MuJoCo* transitions from 64 FetchPush episodes. Inputs are the current 28D robot/object/goal state and 4D bounded action, output is a predicted 28D next state, with the goal held fixed. Checkpoint SHA256: `7e871ea500b41fb9810812b13399f9253a919425a63b6c046ee4d9b15f859a0c`. It is unrelated to WorldDynamics' Cube Dynamics; no fake dimension mapping or cross-robot transfer was performed.

Held-out one-step state MSE in the training record is `1.90e-4` over 392 transitions. A separate 10-seed candidate-replay diagnostic reported mean horizon-1 MSE `1.59e-5`, horizon-3 MSE `4.37e-5`, horizon-3 object XY MSE `1.10e-5`, and mean absolute error in selected sequence terminal cost `0.00446`. These use different sampling/normalization protocols and should not be pooled. Contact-conditioned, friction OOD and long-horizon errors remain insufficiently characterized.

On exploratory seeds 30000–30009, with horizon 3, 16 candidates × 2 CEM iterations, elite 4 and the same bounded action/terminal-cost contract: privileged geometric teacher 9/10; physics-oracle random shooting 10/10; physics-oracle CEM 10/10; learned dynamics CEM 3/10; ensemble-variance penalty 2/10. The oracle snapshots and restores the current MuJoCo state for every counterfactual sequence, whereas learned CEM sees only current state and its own predictions. Neither reads actual future observations at action selection. Raw trajectories and cost predictions are in `artifacts/v12/fetch_push_oracle_10.json`, `fetch_push_learned_10.json` and `fetch_push_dynamics/diagnostics.json`.

The learned planner showed **no benefit** on this small set. Small one-step errors can still change action rankings near contact. Physics-oracle control uses substantial extra simulator calls and is not a deployable world-model benefit. Adaptive horizon, short-horizon ablations, contact error and a new locked confirmation set are **NOT_RUN**; the exploratory settings must not be called optimal.
